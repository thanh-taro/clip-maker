# Code generation adapter

How build scripts turn specs into code (MOD-Build, ADR-0001, ADR-0002, ADR-0014, ADR-0015). Copied
from the sibling image-annotator and adapted. Generated files are checked in, never edited by hand,
and regenerated by `pnpm gen` (also the first step of `pnpm dev` and `pnpm build`). `pnpm check`
runs `pnpm gen:check`, which fails when any checked-in output differs from what the generators
produce.

| Generator | Source (spec) | Output (checked in) | Consumed by |
|---|---|---|---|
| `scripts/gen-tokens.mjs` | `specs/30-experience/tokens.json` (+ the schema's `paletteColour` order) | `src/app/styles/tokens.gen.css`, `src/app/styles/tokens.gen.ts`, `src/core/palette.gen.ts` | all CSS (`var(--tk-…)`), TS token names, the RULE-11 text palette |
| `scripts/gen-types.mjs` | `specs/10-domain/project.schema.json` | `src/core/project.gen.ts` | MOD-Core types (`Project`, `Clip`, `TextLayer`, …) |
| `scripts/gen-copy.mjs` | `specs/30-experience/copy.md` | `src/copy/messages.gen.ts` | MOD-Copy `t(id, params)` |
| `scripts/gen-looks.mjs` | `specs/30-experience/looks.md` (+ copy.md) | `src/core/looks.gen.ts` | `LOOK_IDS`, `LOOK_GROUPS`, `LOOKS` (RULE-09) |
| `scripts/gen-notices.mjs` | `specs/40-technical/dependencies.md` + installed packages | `public/third-party-notices.txt`, `src/app/notices.gen.ts` | shipped at `/third-party-notices.txt`; the in-tool notices view's rows (F-020.R4, compiled into the page) |
| `scripts/gen-headers.mjs` | `src/host/boot.js` + `HOST_ORIGINS` + `TOOL_ORIGIN` | `public/_headers` | Cloudflare static assets (phase 7), `vite preview` (local release preview) |

`scripts/gen-all.mjs` runs all six; `--check` compares instead of writing. Build-time outputs (not
checked in, written into `dist/`): `/sw.js` and `/asset-manifest.json` (`scripts/lib/offline.mjs`).
Still to come with its feature: `gen-looks` table packing (`.cube` → 33³ PNG, F-008), feeding the asset
manifest. (`gen-music-manifest` was removed with the bundled music, D-052.)

## Tokens → CSS custom properties and the text palette
- Style Dictionary 5 (DEP-20) formats the values; the script only splits the colour themes.
- Names: `--tk-<path in kebab case>`, e.g. `color.lineStrong` → `--tk-color-line-strong`,
  `size.toolButton` → `--tk-size-tool-button`, `space.1_5` → `--tk-space-1-5` (the generator turns `_` into `-`). Colour names drop
  the theme segment (`color.dark.bg` and `color.light.bg` are both `--tk-color-bg`).
- Scheme (adapters/design.md, same as the portal): everything inside `@layer tokens`; **dark**
  values and all non-colour tokens on `:root`; **light** colours under `[data-theme="light"]`; a
  `prefers-color-scheme: light` block for `:root:not([data-theme])` (reached only when the boot
  script did not run); `color-scheme` set per theme.
- `contrast` is metadata (checked by `tools/token_contrast.py`), not emitted.
- `palette.gen.ts` exports `PALETTE` and `PALETTE_HEX` from `text.color` so the picture never reads a
  theme (INV-05, ADR-0012 §5). Generation fails unless `text.color` holds exactly the schema's
  `paletteColour` names, in order, as `#RRGGBB`.

## project.schema.json → types
- A dependency-free translator for the subset the schema uses (`type`, `enum`, `const`, `oneOf`,
  `$ref` to `$defs`, arrays, nullable type lists, `required`). Each `$defs` entry becomes a type;
  each top-level array whose items say `ENT-<Name>` becomes `<Name>`; the root is `Project`.
- `allOf` / `if` / `then` / `else` (per-kind clip fields) are not encoded: those fields stay optional.
- Any other keyword fails generation, so a schema change cannot silently weaken the types.

## copy.md → message catalog
- Tables `| ID | en-US | vi-VN | Notes |`: one row per string, the ID cell `**COPY-<group>.<name>**`,
  one text column per language right after ID. The first language is the default (RULE-18).
- A text with a count gives one form per plural category: `one: … · other: …`; a language with a
  single category (vi-VN: `other`) writes its one form without a prefix.
- Generation (and so the build) fails when a string lacks a language, when its `{placeholder}`
  names differ between languages, when its plural forms differ from the language's categories, or
  when a plural string has no `{count}`.
- Output: `LANGUAGES`, `Language`, `CATALOG`, `PLURAL_IDS`, `MessageId`, `MessageParams` keyed by
  the ID without `COPY-`. `t()` requires exactly those parameters at compile time.
- Rows whose Notes say "deprecated" are skipped.

## looks.md → look IDs
- Rows of the looks table with a back-ticked ID (`natural-fresh`). Fails on a duplicate ID or a look
  with no `COPY-look.<id with - as _>` row in copy.md.

## Dependency registry → acknowledgements
- Reads every active DEP row (not `removed`/`rejected`, not a recorded-only fallback). The licence
  cell's SPDX expression is the text before any note.
- For **runtime** and **asset** rows, each npm package named in the row that is installed is listed
  with its installed version, licence and licence file text; MPL-2.0 packages (ADR-0005) also get
  "used unmodified" and a link to the exact source tag of the shipped version. CC-BY rows (build-time
  data) get an attribution line.
- `notices.gen.ts` holds the in-tool view's rows (F-020.R4, "every shipped dependency and asset"):
  `NOTICE_FONTS` (each `@fontsource*` package, titled by its family name), `NOTICE_CODE` (every other
  shipped package, titled `<name> <version>`, source `npmjs.com/package/<name>`, the package's
  licence; then each shipped asset row that is the owner's own work, e.g. DEP-12 and DEP-13, source
  the repository) and `NOTICE_TEXTS` (the notices a registry row says must be kept, "(+ X notice)",
  e.g. DEP-11's Feather MIT notice, in full; generation fails if the text is not in the package's
  licence file).

## Boot script and `_headers`
- `src/host/boot.js` is the only inline script. `scripts/lib/boot.mjs` strips its comment-only
  lines; the Vite plugin inlines exactly those bytes at `<!--boot-->`, and `gen-headers.mjs` puts
  their SHA-256 in `script-src`. Changing the boot script without `pnpm gen` fails `gen:check`.
- `HOST_ORIGINS` (default `https://tarokit.app`; empty → `'none'`; wildcards, paths and non-https
  origins other than localhost refused) sets `frame-ancestors` and the compiled-in `__HOST_ORIGINS__`
  allow-list of MOD-Host. `TOOL_ORIGIN` (default `https://clip-maker.tarokit.app`) is sent as
  `Access-Control-Allow-Origin` on `/assets/*` (the worker and worklet modules, ADR-0014 outcome).
- Rules: `/*` page policy (ADR-0014: `connect-src 'self'`, `media-src 'none'`, no
  `'wasm-unsafe-eval'`, no `blob:`; Permissions-Policy with `fullscreen=(self)` and
  `web-share=(self)`; Referrer-Policy, nosniff, COOP, HSTS, `Cache-Control: no-cache`); `/assets/*`
  1-year immutable + ACAO; `/sw.js` detaches the page CSP for `default-src 'none'; connect-src 'self'`.
- `public/.assetsignore` keeps source maps and the Vite manifest out of the upload.
- `scripts/lib/preview-headers.mjs` makes `vite preview` send `dist/_headers`, so the local release
  preview and the e2e run under the real headers.

## Gates (not generators)
- `scripts/check-licenses.mjs` (`pnpm check:licenses`): `pnpm licenses list --json` against the
  ADR-0001 allow-lists over every installed package, with the named build/dev/test-only exceptions
  (MPL-2.0 `lightningcss*`, `axe-core`, `@axe-core/playwright`; CC-BY-4.0 `caniuse-lite`), OFL for
  registered font assets and the ADR-0005 runtime exception (exactly `mediabunny`, only while its row
  is approved); every direct dependency registered and inside its row's range; production
  dependencies registered as runtime/asset; every transitive production package registered.
  Installed rows not yet `approved` are listed as **PENDING AUDIT**; `--strict` (or
  `LICENCE_STRICT=1`) makes them fail — turned on once the licence audit has approved the rows.
  Then it runs the dist scan.
- `scripts/check-dist.mjs` (`pnpm check:dist`): from the hidden source maps, every third-party
  package whose code reached a shipped chunk (page, workers, worklet) must be a registered
  runtime/asset row under the shipped allow-list (or the ADR-0005 exception); shipped fonts must
  trace to a registered font asset and be a `latin` or `vietnamese` subset; unknown file types fail.
- `scripts/check-size.mjs` (`pnpm check:size`): gzip level 9 of HTML, CSS, the main JS, each worker
  and the worklet, and fonts as they are, against architecture.md "Size"; fails on a JS chunk that
  is neither loaded by index.html nor a worker/worklet, or on any dynamic import (ADR-0002).
- `scripts/check.mjs` (`pnpm check`) runs every gate in order; see `docs/local-dev.md`.
