# Spec questions from the build, for the owner at the wave review
From E1 (MOD-Core/Project/Plan). The behaviour currently built is in [brackets].
1. **F-003.AC8:** 9 min 59 s plus 1 s is exactly 600 s, which RULE-03 allows. Proposal: change the AC to 9 min 59.5 s, as F-009.AC6 already uses. [The AC is not cited by a test; the 59.5 s case is tested under RULE-03.]
2. **RULE-03 vs RULE-05:** RULE-03 accepts an add or duplicate when one frame fits, but RULE-05 sets a 0.1 s minimum length. [Refused when less than the minimum fits.] Proposal: make RULE-03 say "when less than the minimum length fits".
3. **Frame-rate change with adjacent audio clips:** after rounding to the new frame grid they can overlap. [The later clip moves to the next free frame start.] Proposal: add this to RULE-04.
4. **Text fade default** is not stated. [Off.] Proposal: state it in RULE-11.
5. **Cross-fade between clips too short to hold 0.1 s:** no behaviour is specified. [Nothing happens.] Proposal: the cross-fade control is unavailable, with a reason.
6. **Speed change stopped by the minimum length:** no notice is specified. [None shown.] Proposal: show COPY-notice.length_limited, or a new "too short for that speed" notice.
7. **RULE-02 "too short":** it refuses sources shorter than one frame, but sources between 1 frame and 0.1 s become 2-frame clips, which breaks RULE-05's 0.1 s minimum. (From the E1 review.) Proposal: refuse sources shorter than the 0.1 s minimum, rounded up to whole frames, with COPY-reason.too_short. [Built: sources under 0.125 s are refused (0.1 s rounded up at 24 fps, so a later frame-rate change cannot break the minimum). Pending your OK.]

## Technical items from E4 (MOD-Audio). Claude decides these; they are listed for transparency and accepted as built.
8. **MOD-Audio surface `render(audioPlan, fromSample, count)`:** a block plan holds only the voices sounding in that block, but the limiter's 1 s pre-roll needs the voices before it. [Built as `render(voices, sources, endSample, from, count)` plus a streaming `Mixer` and `renderOffline`.] Proposal: update MOD-Audio's public surface.
9. **Verify-and-trim (ADR-0008 outcome rule 2):** "first step = the excess + 0.2 dB" does not say excess over what; "at most 3 passes" does not say if the first encode counts; "a fixed −3 dB trim" does not say relative to what. [Excess over the −1.5 dBTP aim; the first encode counts, so at most 2 trims; the fallback is the last gain − 3 dB, encoded once more and not measured.] Proposal: write these into the ADR outcome or MOD-Audio.
10. **Clock:** ADR-0008 §5 says "`getOutputTimestamp()` minus `outputLatency`", but the output timestamp already describes what reaches the speakers. [The output timestamp is used, carried forward to now; `currentTime − outputLatency − baseLatency` only when there is no timestamp.] Proposal: write it this way in platform-mapping.
11. **Limiter margin:** the −1.5 dBTP ceiling holds on the limiter's own side-chain. Independent meters read up to −1.46 dBTP (BS.1770-4) and −1.39 dBTP (a 64-tap meter) on synthetic +6 dBTP overs. This matches the ADR's "PCM ≤ −1.35 dBTP" and stays inside RULE-12's −1 dBTP. [Tests check ≤ −1.35 on the meters.] No change proposed.
12. **"Underruns counted in debug builds":** there is no debug build flag. [Always counted; it is cheap. The stats come back only on request.] Proposal: drop "in debug builds".

*Items 8–12 applied 2026-11-05 to MOD-Audio, ADR-0008 and platform-mapping (11 needed no change).*

## Items from E5 (MOD-Export/MOD-Scratch). Technical ones are decided by Claude and listed for transparency; behaviour ones need your OK. Updated after the E5 code review and security audit (2026-11-05).
32. **Late sound in the muxer (ADR-0010 outcome item 1, risk 5) — decided.** mediabunny's writer queues every sample in memory until each track has one (`interleaveSamples`, every `fastStart` mode), so writing all video before the sound would hold the video in memory. [Built: video packets made before the verified sound go to a **spill file** (a second scratch file, opened only when needed, same naming so discard and sweep cover it), then are replayed in time order with the sound; MP4 index at the end. The room check is now `estimate × 1.3 + the video's nominal size` (the worst-case spill). Proven in e2e "ADR-0010 outcome item 1 …".] Proposal: name the spill file and the room formula in ADR-0010 outcome items 1/5 and MOD-Scratch.
33. **Clip sound for exports — still to build.** Windowed decoding and 48 kHz resampling (MOD-Audio, ADR-0008 §2/§6) do not exist yet, and the export-audio worker's 10 KB budget cannot hold the container reader. [Built: the export-audio worker takes decoded 48 kHz PCM per source (`PcmSource`). Sound is never dropped silently: if a source heard in the mix has no PCM, the export fails with COPY-error.export_failed before it starts.] Owner of the missing piece: **MOD-Audio (windowed decode + resampler), in the F-011/F-002 sound unit**; for exports the export worker (which has the reader) should send each clip's encoded sound to the export-audio worker, which decodes it with `AudioDecoder` before the video loop starts.
34. **OPEN — square frames vs "long side a multiple of 16" (ADR-0010 outcome item 9).** A 1:1 frame at 1080 cannot be square with a long side that is a multiple of 16. [Built: square stays 1080 × 1080; other aspects get the long side rounded to a multiple of 16, e.g. 4:5 = 1080 × 1344.] Owner decision needed.
35. **Stall watchdog — decided per the MOD-Export spec.** [Built: packets are held one GOP (≈ 2 s) before they reach the muxer; after 20 s without encoder output (also during the final flush) the encoder is closed and re-created, the readers are rewound and encoding restarts at the first frame of the GOP not yet written — the next keyframe boundary of the output — so every frame is in the file once. Only a stall of the re-created encoders (2 restarts) fails the export. `ExportStats.encoderRestarts` records it.] The worker cannot see visibility; a stall while hidden is covered by the interruption rules first.
36. **Shared final gain — decided per ADR-0008 outcome item 2.** Every export of a mix uses its final gain, WAV included. A reused gain is measured; if the decoded peak is above −1.0 dBTP, verify-and-trim runs again from it and the new gain replaces the shared one. The −3 dB fallback encode is not measured.
37. **Size-target corrective pass.** [It rewrites the same scratch file from byte 0 and re-decodes from the start; the progress total doubles, so the bar keeps rising.] Decided. A lower resolution is offered only after its own pre-check passes; the smallest whole-MB target (D-020) uses 480's effective floor measured at its floor bitrate.
38. **The export-audio worker lives in `src/export`** (MOD-Audio does not encode); MOD-Audio gained `TruePeakMeter` and `verifyAndTrim(pass, startDb)` with an unmeasured fallback pass. Decided.
39. **OPEN — colour range tag "as produced" (ADR-0007 outcome item 2).** `fullRange` comes from the encoder's own metadata, else limited. If WebKit writes full range but reports nothing, the tag says limited. The owner's player check should include a WebKit export.
40. **Library names in outputs — decided by F-015.R4 / RULE-15.** [Built without modifying mediabunny (D-042): MOD-Container's writer puts a `NeutralSink` in front of the sink that blanks, in place and across write boundaries, every "Mediabunny…" string the library writes into fixed fields (MP4 `hdlr` names and the `avc1` compressor name with its length byte, WebM MuxingApp/WritingApp, the Ogg Opus vendor string, whose page CRC is recomputed). Creation and modification times are zero. Checked per format by the F-015.AC4 e2e (MP4, WebM, M4A, Ogg, WAV, GIF).]
41. **Abort answer before terminate.** [The result is reported at once; the worker's abort gate closes and deletes its files (also when the abort comes before the sink opened), the worker is terminated after the answer or 1.5 s, and the main thread deletes again, once more after 300 ms if the files are still listed. After `export:done` an abort no longer deletes the finished file; a cancel while the finished file is being opened wins and nothing is saved.] Decided.
42. **F-015.AC14 limit on WebKit:** WebKit partitions storage by top-level site, so the tool embedded in the portal and the tool opened standalone have separate origin-private file systems; each is swept only when the tool next opens in that same context. A page closed embedded leaves its scratch until the tool is next opened embedded. Proposal: note this in F-015.AC14 / INV-01.
43. **Scratch only under the session lock.** Exports use a scratch file only after this session holds its Web Lock (`initScratch()` at boot: lock, then sweep); without Web Locks the memory sink is used (or COPY-error.no_space above the memory cap). The scratch directory is now `clip-maker-scratch`, and only `export-<session>-<random>.part` names are ever opened. Decided.
44. **Liveness and dead workers.** Silent phases (waiting for the sound, spill replay, writing the index, verify-and-trim decodes) post liveness beats, and in a video export the export-audio worker's beats count too, so hide-and-return does not interrupt a working export. A worker `error`/`messageerror`, 30 s of silence from the export worker while visible, 30 s of silence from the export-audio worker while the video waits for it, or a sound codec queue that does not move for 20 s fails the export with COPY-error.export_failed. A storage quota error is COPY-error.no_space. Decided.
45. **F-015.AC11 measurement note:** the estimate's sound part uses the trial's delivered rate on dense audio. On pure tones WebKit's AAC delivers far less (≈ 56 vs 139 kbps), so a short, tone-only project can be over-estimated by more than 25 % on WebKit. The AC11 e2e uses dense, music-like sound; the fixture projects (real music) should be measured in QA.
